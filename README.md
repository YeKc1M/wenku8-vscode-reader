# Workspace Notes · Wenku8

安装一个 VSIX，在 VS Code 内阅读文库吧轻小说。**不需要 Kimi、浏览器扩展、外部 Chrome、守护进程、代理中继或额外下载的浏览器。** 运行环境为桌面版 VS Code 1.142.0 或更新版本；其自带的 JavaScript Debugger 用于网站要求的安全验证。

正文显示在原生只读 `workspace.ts` 编辑器中，转换为 TypeScript 字符串数组，具有真正的语法高亮、行号、查找和拆分布局。dark / light / 高对比度自动跟随 VS Code 主题。标签和正文默认不显示书名、章节名及插图；本地书架位于资源管理器折叠的 **Workspace Notes** 视图。

## 安装与开始

1. 在扩展面板选择 **从 VSIX 安装**，安装 `wenku8-vscode-reader-0.5.0.vsix`。
2. 执行 **Wenku8: 添加书籍链接或 ID**，输入 `3057` 或文库吧书籍 / 目录 / 章节 HTTPS 链接。
3. 插件先直接向网站请求内容。若网站要求 Cloudflare 验证，点击提示中的 **在 VS Code 内验证**，或执行同名命令。
4. 在 VS Code 内置页面完成安全验证。可以在该页登录，也可以稍后通过 **Wenku8: 登录账号** 输入账号和密码。
5. 执行 **Wenku8: 验证完成**。网站页面会被替换为普通工具函数，标签变为 `session.ts`；回到阅读器重新打开书籍即可。

`session.ts` 保持网站网络会话，不展示小说和原站首页。请保留这个页签；关闭它会结束当前浏览器连接，下次可能需要重新验证。会话页底层仍属于原站地址，选择它时内置浏览器地址栏可能显示网站域名。正文阅读使用独立的 `workspace.ts`，不是嵌入网站。

网站验证由站点决定，不能保证永远免验证；本次在 VS Code 内已实际验证目录、正文、账号登录和登录后搜索。

## 阅读操作

| 操作 | 入口 |
| --- | --- |
| 书架 / 恢复 | `Wenku8: 打开 / 恢复阅读` |
| 搜索 | `Wenku8: 搜索书名或作者`，结果支持手动翻页 |
| 导入网站书架 | `Wenku8: 导入网站书架`，选择分组和书籍，只修改本地数据 |
| 选择分卷 / 章节 | `Ctrl+Alt+J`，macOS `Cmd+Alt+J`，或同名命令 |
| 上 / 下一章 | `Alt+←` / `Alt+→` |
| 隐藏 | `Ctrl+Alt+H`，macOS `Cmd+Alt+H`；正文聚焦时也可按 `Esc` |
| 查看插图 | `Wenku8: 查看本章插图`，单独打开 `assets` 面板 |
| 刷新 | `Wenku8: 刷新目录和章节` |
| 移除本地书籍 | 书架右键或 `Wenku8: 从本地书架移除` |

隐藏会替换内容提供器正文，关闭所有分组的阅读标签和插图面板，清空书架视图条目并隐藏状态栏入口。窗口失焦时默认执行相同操作。正在读取的旧请求不能恢复正文；回来后必须明确执行恢复命令。

自动保存每本书的最近章节和可见行位置，支持旧版书架及滚动比例。正文只做有界内存缓存，不写入工作区文件，不批量下载整本书。代码外观和隐藏功能不能保证旁观者无法识别中文内容，VS Code 自身也可能保留编辑历史。

## 设置与会话

| 设置 | 默认 | 说明 |
| --- | --- | --- |
| `wenku8.hideOnBlur` | `true` | VS Code 窗口失焦时隐藏 |
| `wenku8.wrapColumn` | `52` | 字符串每行字符数，20–120，下次打开章节生效 |

字号、行高与主题使用 VS Code 的编辑器设置。旧版桥接地址、字体和插图配置不再使用，插图改为按需打开。

直接请求的 Cookie 存在 VS Code SecretStorage 中；内置浏览器 Cookie 由 VS Code 的浏览器存储策略管理。插件不保存密码。会话失效后需重新登录或验证；选择浏览器临时存储模式时，关闭会话或重启后可能需要重新验证。

**Wenku8: 退出登录** 清除插件的 HTTP 会话及内置浏览器中本站的 Cookie，保留本地书架和进度。内置浏览器可能与其他 VS Code 网站页签共享本站 Cookie，因此这些页签也会退出。本版不依赖 0.4 的外部浏览器会话，也不会操作外部浏览器中的登录。

## 开发与验证

```sh
npm ci
npm test
npm run package
```

按 `F5` 启动开发宿主。`npm test` 覆盖解析、GBK、Cookie 恢复、重定向地址限制、登录失败和原生会话请求脚本。

`test/extensionHost.cjs` 使用模拟网站验证真实原生编辑器、dark/light 切换、进度、章节导航、拆分隐藏及请求竞争。运行时传独立的 `--user-data-dir`；测试会修改该目录的主题设置。

`npm run test:live` 启动隔离的 VS Code 窗口，直接检查真实网站和内置浏览器会话，不使用外部桥接。需要安全验证时，在测试窗口内手动完成；60 秒内未完成会报错。可设置 `VSCODE_EXECUTABLE` 指向 VS Code 实际可执行文件。可选环境变量 `WENKU8_TEST_USERNAME` / `WENKU8_TEST_PASSWORD` 启用登录后搜索检查；测试脚本不打印凭据，结束后清理临时用户目录。截图与结果放在忽略提交的 `artifacts`。

内置浏览器接入通过随 VS Code 提供的调试器实现，其中 CDP 代理和页签标识属于内部接口；已在 macOS / VS Code 1.142.0 实测，未来版本可能需要适配。vscode.dev 不支持，Remote SSH / WSL 尚未实测。协议记录见源码中的 `docs/site-analysis.md`。
